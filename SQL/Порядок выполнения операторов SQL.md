# Порядок выполнения операторов SQL

Пишем запрос сверху вниз, но СУБД выполняет его в другом порядке.

![[порядок выполнение операторов.png]]

```mermaid
flowchart LR
    FROM --> WHERE --> GROUP[GROUP BY] --> HAVING --> SELECT --> DISTINCT --> ORDER[ORDER BY] --> LIMIT --> OFFSET
```

| № | Оператор | Что делает | Видит алиасы из SELECT? |
| --- | --- | --- | --- |
| 1 | `FROM` / `JOIN` | источники и соединения | нет |
| 2 | `WHERE` | фильтр строк до группировки | нет |
| 3 | `GROUP BY` | группировка | нет (в Postgres можно по номеру/алиасу) |
| 4 | `HAVING` | фильтр групп (агрегаты) | нет |
| 5 | `SELECT` | вычисление выражений, алиасы | — |
| 6 | `DISTINCT` | убрать дубликаты | да |
| 7 | `ORDER BY` | сортировка | да |
| 8 | `LIMIT` / `OFFSET` | срез результата | да |

> [!tip] Почему `WHERE avg_x > 5` не работает
> `WHERE` выполняется раньше `SELECT`, алиаса ещё не существует. Для агрегатов нужен `HAVING`.
