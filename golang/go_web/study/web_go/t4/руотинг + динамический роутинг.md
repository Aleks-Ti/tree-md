## Идея

Роутинг связывает пару «HTTP-метод + путь» с обработчиком. Динамический роутинг использует параметры пути `:name`, значение берётся через `c.Params("name")`. Состояние в уроке хранится в глобальных переменных в памяти процесса.

## Статический роутинг (theory/0)

```go
webApp.Get("/about", func(c *fiber.Ctx) error {
    return c.SendString("The best school for Software Engineers")
})
webApp.Get("/courses", func(c *fiber.Ctx) error {
    return c.SendString("Java, Go, Python")
})
```

## Разные методы на одном пути (theory/1)

```go
var counter int64 = 0

webApp.Get("/counter", func(c *fiber.Ctx) error {
    return c.SendString(strconv.FormatInt(counter, 10))
})
webApp.Post("/counter", func(c *fiber.Ctx) error {
    counter++
    return c.SendStatus(fiber.StatusOK)
})
```

## Динамический роутинг (theory/2)

```go
var counters = make(map[string]int64)
const requestParamKeyEvent = "event"

webApp.Get("/counter/:event", func(c *fiber.Ctx) error {
    event := c.Params(requestParamKeyEvent, "")
    if event == "" {
        return c.SendStatus(fiber.StatusUnprocessableEntity)
    }
    eventCounter, ok := counters[event]
    if !ok {
        return c.SendStatus(fiber.StatusNotFound)
    }
    return c.SendString(strconv.FormatInt(eventCounter, 10))
})

webApp.Post("/counter/:event", func(c *fiber.Ctx) error {
    // ...
    counters[event] += 1
    return c.SendStatus(fiber.StatusOK)
})
```

## ДЗ: лайки постов (dz)

`GET /likes/:post_id` возвращает счётчик или 404; `POST /likes/:post_id` создаёт счётчик (201, тело `1`) либо увеличивает его (200):

```go
webApp.Post("/likes/:post_id", func(c *fiber.Ctx) error {
    param := c.Params(patrParametrs, "null")
    _, ok := postLikes[param]
    if !ok {
        postLikes[param] = 1
        return c.Status(fiber.StatusCreated).SendString("1")
    }
    postLikes[param] += 1
    return c.SendString(strconv.FormatInt(postLikes[param], 10))
})
```

## Запуск и проверка

```bash
go run .
curl -X POST http://localhost:80/counter/login      # theory/2
curl http://localhost:80/counter/login              # 1
curl -i http://localhost:80/counter/unknown         # 404
curl -i -X POST http://localhost:80/likes/p1        # dz: 201, тело 1
curl -X POST http://localhost:80/likes/p1           # 2
curl http://localhost:80/likes/p1                   # 2
```

## Подводные камни

- Глобальные `map` и счётчики не потокобезопасны: при параллельных запросах возможна гонка (см. [[хранение данных in memory и мини бек с map]], там `sync.Mutex`). Запись в map из нескольких горутин может привести к панике.
- Данные теряются при перезапуске.
- Параметр `:event` не матчит пустую строку, так что проверка `event == ""` фактически мёртвый код, но безвредный.
- В dz слушается `:80` (как и в theory), а не `:8080`.
