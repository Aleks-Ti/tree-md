## Идея

Сериализация — превращение структуры Go в JSON-строку (`json.Marshal`) и обратно (`json.Unmarshal`). Имена полей в JSON задаются тегами `json:"..."`. В Fiber тело запроса разбирается через `c.BodyParser(&req)`, ответ отдаётся через `c.JSON(obj)`.

## encoding/json (theory/0)

```go
type User struct {
    ID       int64  `json:"id"`
    Email    string `json:"email"`
    Name     string `json:"name"`
    Age      int    `json:"age,omitempty"` // нулевое значение не попадёт в JSON
    password string                         // неэкспортируемое поле игнорируется
}

jsonBytes, err := json.Marshal(&user)
deserializedUser := User{}
err = json.Unmarshal(jsonBytes, &deserializedUser)
```

## JSON в HTTP (theory/1)

```go
webApp.Post("/logs", func(c *fiber.Ctx) error {
    var request CreateLogEntryRequest
    if err := c.BodyParser(&request); err != nil {
        return fmt.Errorf("body parser: %w", err)
    }
    logEntry := LogEntry{ID: uuid.New().String(), Message: request.Message,
        Level: request.Level, Timestamp: request.Timestamp}
    logs = append(logs, logEntry)
    return c.JSON(CreateLogEntryResponse{ID: logEntry.ID})
})
```

Отдельные структуры для запроса, ответа и внутренней модели (`CreateLogEntryRequest`, `CreateLogEntryResponse`, `LogEntry`).

## ДЗ: поиск числа (dz)

`POST /search` принимает `{"numbers": [...], "target": N}`:

```go
err := c.BodyParser(&request)
if err != nil {
    response.TargetIndex = targetNotFound
    response.Error = "Invalid JSON"
    return c.Status(fiber.StatusBadRequest).JSON(response)
}
result_index := slices.Index(request.Numbers, request.Target)
if result_index == targetNotFound {
    response.Error = "Target was not found"
    return c.Status(fiber.StatusNotFound).JSON(response)
}
```

## Запуск и проверка

```bash
go run .
curl -X POST http://localhost:80/logs -H "Content-Type: application/json" \
  -d '{"message":"hello","level":"info","timestamp":1700000000}'
curl -X POST http://localhost:8080/search -H "Content-Type: application/json" \
  -d '{"numbers":[1,3,5,7],"target":5}'          # {"target_index":2}
curl -i -X POST http://localhost:8080/search -H "Content-Type: application/json" \
  -d '{"numbers":[1,3],"target":9}'              # 404
```

## Подводные камни

- `BodyParser` выбирает парсер по заголовку `Content-Type`; без `application/json` JSON не разберётся.
- Возврат `fmt.Errorf(...)` из обработчика даёт клиенту 500, а не 400.
- Неэкспортируемые поля (`password`) в JSON не попадают, но и из JSON не читаются.
- `omitempty` скрывает и легитимный ноль (`age: 0`).
- В dz название говорит про бинарный поиск, но реализован линейный `slices.Index` (не требует отсортированности). В ответе `target_index` не `omitempty`, поэтому индекс 0 отдаётся корректно.
- В dz увеличен `ReadBufferSize` (буфер чтения запроса) до 16 КБ; это настройка шаблона ДЗ, к JSON напрямую не относится.
